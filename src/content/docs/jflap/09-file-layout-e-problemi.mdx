## Il formato `.jff`

I file di JFLAP sono semplici file di testo in formato **XML**. Aprendone uno con un editor (Blocco note, VS Code) si vede la struttura dell'automa: è un bel collegamento con la **definizione formale** come quintupla.

```xml
<?xml version="1.0" encoding="UTF-8" standalone="no"?><structure>
	<type>fa</type>                       <!-- fa, mealy, moore, pda, turing... -->
	<automaton>
		<state id="0" name="q0">            <!-- un elemento di Q -->
			<x>160.0</x>
			<y>185.0</y>
			<initial/>                        <!-- q0 è lo stato iniziale -->
		</state>
		<state id="1" name="q1">
			<x>360.0</x>
			<y>185.0</y>
			<final/>                          <!-- q1 appartiene a F -->
		</state>
		<transition>                        <!-- δ(q0, a) = q1 -->
			<from>0</from>
			<to>1</to>
			<read>a</read>                    <!-- <read/> vuoto = λ-transizione -->
		</transition>
	</automaton>
</structure>
```

- Ogni `<state>` ha un numero (`id`), un nome, la posizione nel disegno e, se serve, i marcatori `<initial/>` e `<final/>`.
- Ogni `<transition>` collega due stati tramite il loro `id` e indica il simbolo letto. Nelle macchine di **Mealy** c'è anche `<transout>` (l'uscita); nelle macchine di **Moore** ogni stato ha un `<output>`.
- L'**alfabeto** non è scritto da nessuna parte: JFLAP lo ricava dai simboli usati nelle transizioni.

<Aside type="tip" title="Un'idea per il docente">
Siccome il formato è testuale, si possono **generare** automi con un programma (per esempio in Python), oppure scrivere uno script che controlla i file consegnati dagli alunni (numero di stati, presenza dello stato iniziale…). È anche un ottimo esercizio di collegamento con XML per le classi che lo studiano.
</Aside>

## Preferenze

Le preferenze si impostano dalla **finestra principale** di JFLAP, menu **Preferences**:

| Preferenza | Cosa cambia |
| :-- | :-- |
| **Set the Empty String Character** | il simbolo della stringa vuota: **λ** (predefinito) oppure **ε** |
| **Set Undo Amount** | quante operazioni si possono annullare (predefinito 50) |
| **Turing Machine Preferences** | opzioni per le macchine di Turing (non servono per gli automi a stati finiti) |

Le preferenze vengono salvate nel file **`jflapPreferences.xml`**, nella stessa cartella del programma.

## Il menu View: rimettere ordine

Dopo una conversione gli automi prodotti da JFLAP possono essere difficili da leggere. Nel menu **View** dell'editor:

- **Save Current Graph Layout** / **Restore Saved Graph Layout**: salva la disposizione attuale e la ripristina (utile prima di sperimentare);
- **Move Vertices**: rifletti il grafo rispetto a una linea, ruotalo, allargalo per riempire la finestra;
- **Apply a Specific Layout Algorithm**: dispone automaticamente gli stati in cerchio (*Circle*), a due cerchi, a spirale, ad albero (*Tree*), con l'algoritmo *GEM* o a caso;
- **Apply a Random Layout Algorithm**: ne sceglie uno a caso.

Per gli automi "in fila" (come i rilevatori di sequenza) il layout ad **albero** dà spesso buoni risultati; per i cicli (contatori modulo *n*) il layout **circolare**.

## Problemi frequenti e soluzioni

| Problema | Causa probabile | Soluzione |
| :-- | :-- | :-- |
| Il doppio clic su `JFLAP7.1.jar` non fa nulla o apre WinRAR | Java non installato o i file `.jar` non sono associati a Java | Installare Java; tasto destro → *Apri con* → Java; oppure `java -jar JFLAP7.1.jar` dal terminale |
| La finestra è minuscola e illeggibile | schermo ad alta risoluzione su Windows | Proprietà di `javaw.exe` → Compatibilità → impostazioni DPI → *Sistema* |
| Non riesco a creare una transizione | non è selezionato il **Transition Creator**, oppure il trascinamento è partito fuori dallo stato | selezionare lo strumento giusto e iniziare il trascinamento **dentro** il cerchio |
| L'automa accetta stringhe che non dovrebbe | stato iniziale anche finale per sbaglio; transizione verso lo stato sbagliato | **Multiple Run** con la stringa vuota e con stringhe "quasi giuste"; **View Trace** sulla riga sbagliata |
| L'automa rifiuta stringhe che dovrebbe accettare | transizione mancante (l'automa si blocca); stato finale non marcato | **Step with Closure** e osservare dove si ferma la configurazione |
| "Highlight Nondeterminism" colora stati in un esercizio sui DFA | due transizioni con lo stesso simbolo dallo stesso stato, oppure una λ-transizione | trovare la freccia doppia (spesso è un'etichetta scritta male) |
| Una transizione "0,1" non funziona | JFLAP la interpreta come la stringa `0,1` | cancellarla e creare due transizioni separate |
| La stringa vuota non viene provata | si è scritto "λ" o "ε" nella casella | lasciare la casella **vuota**; in Multiple Run usare **Enter Lambda** |
| Un'espressione regolare dà risultati strani | ci sono **spazi** nell'espressione | togliere tutti gli spazi |
| Minimize DFA o Add Trap State non funzionano | l'automa non è deterministico | prima **Convert to DFA** |
| La macchina di Mealy/Moore non parte | ci sono stati non deterministici | controllare che da ogni stato esca al massimo una transizione per simbolo |
| Il file non si apre su un altro computer | versione diversa di JFLAP o file corrotto | usare la stessa versione (7.1) su tutte le postazioni |

<Aside type="caution" title="Salvare spesso">
JFLAP è un programma stabile ma "vecchio stile": non ha il salvataggio automatico. Abituare gli alunni a salvare (**File → Save**) dopo ogni passaggio importante, e prima di lanciare una conversione.
</Aside>
